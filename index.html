How It Works

A real 74,744-book catalog, the same production recommender as the live Android app — but your taste lives only in this tab (refresh = reset). No backend, no user rows.

1 — Book embeddings \( \mathbf{v}\in\mathbb{R}^{768} \)

Cover art via SigLIP 2 (vision-language) + title/author/description via bge-base (text) are fused into one L2-normalized 768-d vector per book and indexed in pgvector HNSW (binary-quantized). Similar books are close under cosine distance \( d_{\cos}=1-\cos(\mathbf{a},\mathbf{b})\). The map below shows the same vectors after UMAP to 3D.

2 — Taste that drifts (max 5 clusters + 1 disliked)

Every Like / Save / Interested pushes your taste; Not for me pushes a separate disliked centroid. Onboarding just seeds the same machinery using the genre anchors' sub1..5 sub-centroids.

Merge or create:

\[ d_{\cos}(\mathbf{v}, \mathbf{c}_{\text{nearest}}) \le 0.45 \;\Rightarrow\; \text{merge, else new cluster} \] \[ \mathbf{c}_{\text{new}} = \operatorname{normalize}\big(\,w_{\text{old}}\mathbf{c}_{\text{old}} + 1\cdot\mathbf{v}\,\big),\quad w_{\text{new}}=w_{\text{old}}+1 \] \[ w_i \leftarrow 0.95\,w_i\ \text{on every taste signal (decay)},\quad |\mathcal{C}|\le 5\ \text{(LRU evict at cap)} \] \[ \mathbf{c}_{\text{dis}} \leftarrow \operatorname{normalize}(0.90\,\mathbf{c}_{\text{dis}}+\mathbf{v}),\quad w_{\text{dis}}\leftarrow 0.90\,w_{\text{dis}}+1 \]

Onboarding: union all sub1..5 for picked genres + any loved-book vectors → k-means (\(k=\min(5,|seeds|)\), spread init \(i\cdot n/k\)) → \(\le 5\) centroids. Identical to prod _apply_taste_signal / _apply_disliked_signal / _kmeans_halfvec.

3 — Unified scoring + MMR (no distance rings)

Warm users pull from taste + exploration; cold users from trending + exploration. Taste = ANN against top-3 clusters; trending/exploration = quality random pool. Every candidate is scored once:

\[ \text{score}(\mathbf{v}, s)=\;w_t\,t + w_g\,g + w_q\,q + w_f\,f,\quad (w_t,w_g,w_q,w_f)=\begin{cases} (0.45,0.25,0.20,0.10) & s=\text{taste}\\ (0.25,0.15,0.45,0.15) & s=\text{trending}\\ (0.20,0.10,0.15,0.55) & s=\text{exploration} \end{cases} \]
  • \(t = \max_{c\in\mathcal{C}}\cos(\mathbf{v},c) - 0.35\cdot\max(0,\cos(\mathbf{v},\mathbf{c}_{\text{dis}}))\) — taste after disliked penalty
  • \(g = \mathbf{1}[\,\text{book genres}\cap\text{picked genres}\neq\varnothing\,]\) — genre match (0/1)
  • \(q = 0.4\frac{r}{5}+0.4\min(\frac{\log_{10}N}{5},1)+0.2\mathbf{1}_{\text{NYT}}\) — rating \(r\), count \(N\)
  • \(f = \frac{1}{1+\ln(1+\text{shown})}\) — freshness sinks repeatedly shown books

Top-scored pool is then diversity-reranked with Maximal Marginal Relevance:

\[ \text{MMR}(\mathbf{v}) = \lambda\cdot\text{score}(\mathbf{v}) - (1-\lambda)\cdot\max_{\mathbf{p}\in\text{picked}}\cos(\mathbf{v},\mathbf{p}) \] \[ \lambda = \operatorname{clip}_{[0.35,0.85]}\!\big(0.25+0.65\max(0,1-\tfrac{\text{cov}}{0.01})\big),\quad \text{cov}=\tfrac{|\text{seen}|}{74\,730},\quad \lambda\ge 0.55\ \text{if cold} \]

Small \(\text{cov}\) → low \(\lambda\) → more exploration; as you consume, \(\lambda\) rises toward relevance. The “How This Feed Was Built” card shows the exact \(\lambda\), sources, and picks.

4 — Quality gate (Strict, feed-only)

Feeds (For You / Daily / Picked) are Strict — identical to prod _quality_gate: \(\text{ratings}\ge 5{,}000 \;\; \lor\;\; \text{NYT} \;\; \lor\;\; (\text{manga}\land r\ge 4.0)\). Only 34,655 / 74,730 books (~46%) pass and can appear in feeds. The rest are search-only — use the Search tab to find any title by name, even below the gate. No relaxed fallback, no cold-start bypass. Search does not apply the gate.

Stack: vanilla JS + Supabase read-only RPCs (match_books_nearest, random_popular_seed, get_genre_anchors) over pgvector HNSW · covers from Cloudflare R2 · taste in sessionStorage only. Prod SQL: 20260902000000_unified_mmr_recommendations.sql.
