How It Works

This demo runs a production recommendation engine on a real catalog of 74,744 books. Every interaction you had — liking, skipping, saving — fed into the same clustering and serving logic that powers the live app.

Book Embeddings

Each book is converted into a 768-dimensional vector using two models working together. SigLIP 2 (a vision-language model from Google) encodes the cover art into a dense representation. bge-base (a text embedding model from BAAI) encodes the title, author, and description. These two signals are blended into a single 768-d vector and stored in pgvector (a Postgres extension for vector similarity search). Books with similar covers, themes, or writing style end up close together in this space — that's what every faint dot on the map represents.

Dynamic Taste Clustering

When you like or save a book, its vector is compared against your existing taste clusters. If it's close enough (cosine distance ≤ 0.45), it merges into the nearest cluster with a weight-scaled L2-normalized update (centroid = normalize(centroid·wold + vec·1)); if it's too far, a new cluster is created. Up to 5 clusters coexist — so enjoying both science fiction and romance doesn't collapse into a single average. Each cluster's weight decays by 0.95 per taste signal so old preferences fade unless reinforced; the least-recently-used cluster is evicted at capacity. A separate disliked centroid (decay 0.90, penalty 0.35) tracks your "Not for me" signals so the scorer can push similar books down without polluting taste. Onboarding unions the sub1..5 sub-centroids for each chosen genre and k-means them to ≤5 with the same _kmeans_halfvec spread init — the same code the live Android app uses.

Unified Scoring + MMR

The retired distance-ring model is gone. Every candidate is now scored with a single _recommend_score and then diversity-reranked with _mmr_rerank — identical to production (20260902000000_unified_mmr_recommendations.sql):

  • Taste books come from ANN nearest against your top-3 clusters; trending and exploration come from the quality random pool. Warm users get taste + exploration, cold users get trending + exploration.
  • Score per source: taste 0.45/0.25/0.20/0.10 (taste/genre/quality/freshness), trending 0.25/0.15/0.45/0.15, exploration 0.20/0.10/0.15/0.55. Taste similarity is max cosine to any positive cluster minus 0.35·sim(disliked); genre match is 1 if the book shares a picked genre; quality mixes normalized rating + log10(ratings_count) + NYT boost; freshness is 1/(1+ln(1+shown_count)) so seen books sink.
  • MMR reranks the top-scored pool: mmr = λ·score − (1−λ)·maxSimToPicked. λ is coverage-driven — 0.25 + 0.65·max(0,1−cov/0.01) clamped to 0.35–0.85 (high diversity when you've seen little, more relevance as coverage grows; cold users floor at 0.55). The pipeline card shows the exact λ, sources, and picked counts for your feed.

No hard ring percentages — the balance of relevance vs. discovery falls out of the weights + MMR, with the strict quality gate still applied via the quality component.

Quality Gates

Every candidate book passes through the same strict quality gate before it can appear in a feed. A book qualifies if it has 5,000+ ratings, is a NYT bestseller, is manga rated ≥ 4.0, or comes from the curated catalog scrape. There is no relaxed mode and no cold-start exception — the bar is identical for every user, on every feed, so low-quality or obscure books never crowd out strong ones.

The Vector Space Map

The map is a 2D projection (PCA) of the full 768-dimensional book space. It preserves relative distances — books that are close on the map are semantically similar. The background scatter shows the overall shape of the catalog. Your explored books appear as colored dots (green for likes, indigo for interested, red for skips). The taste clusters are larger indigo blobs whose size reflects weight. The drift trails show how clusters move as you interact — each point is a snapshot of the centroid position after a signal.

Technology Stack

This is a fully static, no-backend demo. The frontend is vanilla JavaScript that renders covers straight from Cloudflare R2 and calls read-only Supabase RPCs running against the real catalog stored in pgvector with a binary-quantized HNSW index (sub-millisecond ANN search). The book vectors are pre-computed with SigLIP 2 + bge-base (768-d). Your taste profile (5 clusters + disliked centroid) lives only in your browser memory for this session — it is never stored or sent anywhere — and the feed is assembled client-side from the same unified scoring + MMR logic the live Android app uses (coverage-driven λ, per-source weights, scored pools → MMR rerank). Refresh the page and the taste resets. Cover images come from Cloudflare R2.

Built as a portfolio project to demonstrate real-time recommendation systems.
